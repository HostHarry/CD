# MMMU r50 生成模式：更多替换、更少等待与质量变化

本报告比较相同 900 道题上的 CDAPC r50、r90 和 Native。r50 与 r90 的方法参数只改变 r gate 阈值（0.5 对 0.9）；alpha=0.5、beta=0.1、u gate=0.1、W=K=16、256-token 画布和 EOS 前缀停止规则保持一致。分析来自已有生成记录与评分，没有新增模型推理或 judge 请求。

**r50 确实更常执行对比替换，同时减少门控等待和生成耗时。这批数据上，它的正文结构更不稳定、空推理更多，judge 判对数低于 r90。**

## 1. 速度提升来自更宽松的接受门槛及更早停止

| 指标 | r90 | r50 |
| --- | ---: | ---: |
| 平均迭代次数 | 77.83 | 31.37 |
| 平均模型前向次数 | 155.66 | 62.75 |
| 平均生成耗时 | 28.92 秒 | 11.69 秒 |
| 平均 EOS 前输出长度 | 114.62 tokens | 95.44 tokens |
| 平均每轮提交数 | 2.80 | 4.93 |
| fallback 迭代比例 | 48.23% | 18.55% |
| 正文 token 由 fallback 写入的比例 | 32.23% | 6.03% |
| `eos_prefix_complete` 提前停止 | 214/900 | 574/900 |

r50 的平均生成速度是 r90 的约 2.47 倍、Native 的约 1.70 倍。耗时不包括预处理、加载和评分。

r50 的 qualified 正文 token，原始视觉概率均值为 0.755、中位数 0.781；r90 对应为 0.965 和 0.985。这不是正确率，而是说明 r50 会接受视觉分支自身没有那么确定的位置，从而减少等待。

## 2. 对比机制更常改变实际写入

| 指标 | r90 | r50 |
| --- | ---: | ---: |
| 窗口观测中 contrast ≠ base | 21.57% | 21.56% |
| 实际非 base 写入 | 182 | 2,949 |
| 其中位于最终 EOS 前 | 166 | 2,557 |
| 至少一次实际替换的题目 | 174/900 | 801/900 |
| 最终可见文本中发生替换的题目 | 160/900 | 700/900 |
| qualified 正文写入中，候选池仅一个 token | 95.67% | 52.77% |

两组产生不同候选的观测比例接近，差异主要体现为接受与提交路径。r50 的实际替换次数约为 r90 的 16.2 倍，且多数出现在可见文本中。

候选观测会重复计算同一位置在不同轮次的状态；两组轨迹已经不同，不能把上述观测率当作对相同 logits 的配对统计。

## 3. 更多答案位置替换，不等于更多“错误字母→正确字母”

在完整 `</think>` 后能定位明确选项字母的题中：

- r50 有 291 道，160 道（54.98%）在正文还没填完时已写答案；r90 为 343/491（69.86%）。
- r50 的 46 道在该答案 token 上发生了非 base 替换；r90 为 3 道。
- 这 46 次的 base 中，**32 次是 EOS**，4 次是换行；只有 **4 次是一个合法选项字母改成另一个合法选项字母**。

四次局部字母替换：

| 样本 | 同状态 base → 实际写入 | Gold | 局部字母结果 |
| --- | --- | --- | --- |
| `validation_Accounting_12` | A → C | A | 正确字母改错 |
| `validation_Biology_6` | B → C | B | 正确字母改错 |
| `validation_Clinical_Medicine_21` | C → B | B | 错误字母改对 |
| `validation_Diagnostics_and_Laboratory_Medicine_25` | B → A | B | 正确字母改错 |

这是很小的、按最终输出筛选的子集，不能代表全部 2,949 次替换。base 指同一 r50 解码状态的视觉 top-1，不是 Native 或 r90 的完整生成结果；没有执行写回 base 的反事实续写。

两个具体例子：

- **Biology_6**：base B 的视觉概率为 0.615，contrast C 为 0.373；对比 gain 使 C 的 r 达到 0.525，通过 r50 门控。最终 C 错误。r90 在自己的轨迹中回答 A，也错误，所以不能推断在 r50 同状态拒绝这次替换就等于 r90 会答对。
- **Clinical_Medicine_21**：base C 的视觉概率为 0.289，contrast B 为 0.255，B 的 r 为 0.511；最终 B 正确。但其 244-token 输出正文大量重复 `abdominal`。答案得分改善并不保证推理正文质量改善。

这 46 道答案 token 替换题，相对 r90 是 7 道改对、7 道改错，净变化 0；这是事后分组的描述，不是替换的因果效应。

## 4. 提前 EOS 和结构破坏增多

| 文本现象 | Native | r90 | r50 |
| --- | ---: | ---: | ---: |
| 文本恰好为 `<think>` | 83 | 80 | 113 |
| 有 `</think>` 且其后有非空文本 | 455 | 616 | 415 |
| 有 `<think>`，没有 `</think>` | 207 | 160 | 376 |
| 出现 `TheThe` | 0 | 3 | 15 |
| 出现 `thinkthink` | 0 | 1 | 14 |

r50 的 113 条空推理全部被 judge 判错，平均 1.49 步、中位数 1 步就结束。其中 **40 条的终止 EOS 是 contrast 替换了非 EOS 的 base**，r90 对应为 12 条。

相对 r90：

- 45 道从其他输出变成只有 `<think>`，其中 11 道原本被 r90 判对；
- 12 道从只有 `<think>` 变成其他输出，其中 2 道在 r50 判对；
- 279 道失去“闭合 think + 后续文本”的结构，78 道反向获得这种结构。

这些组可能重叠，不能把各组的准确率变化直接相加，更不能把生成结果分组当作随机消融。

376 条未闭合 think 不等于 376 条达到长度上限：r50 只有 4 条没有 EOS 且达到 256 tokens。多数这类输出是在更早的位置结束，或出现了格式异常。

## 5. 尾部 EOS 仍然会阻挡前缀

r50 仍有 **321/900 道题**出现“已经知道 EOS，但本轮只写 EOS 后位置”的情况，共 2,873 轮，占所有迭代的 10.17%。其中 2,870 轮走 qualified，3 轮走 fallback。

最慢的 `validation_Chemistry_4` 最终只输出 **64 tokens，却用了 129 步**。第 27–122 步连续 96 轮仅写尾部，最后一轮才以 fallback 补上前文位置 20 的 ` mirror`，最终答案仍错误。

降低阈值缓解了这个问题，但没有改变“尾部 eligible 阻止前缀 fallback”的调度逻辑。前文和尾部的竞争仍值得单独处理。

## 6. Official 略高，是随机 fallback 抵消了解析成绩下降

| 评分 | Native | r90 | r50 |
| --- | ---: | ---: | ---: |
| LLM judge | 227/900（25.22%） | 247/900（27.44%） | 219/900（24.33%） |
| Strict | 170/900（18.89%） | 205/900（22.78%） | 164/900（18.22%） |
| Official | 250/900（27.78%） | 266/900（29.56%） | 267/900（29.67%） |
| 规则解析失败 | 315 | 236 | 375 |
| Official 随机 fallback 猜对 | 80 | 61 | 103 |

逐条核对后，所有“official 正确但 strict 错误”的记录都来自 `strict_status=unparsed`。本项目 official 轨道对解析失败的选择题使用按样本固定种子的随机选择，strict 轨道把这些情况记为 0。

因此 r50 对 r90 的 official 变化可以精确拆成：

```text
Strict 判对减少 41 道 + 随机 fallback 多猜对 42 道 = Official 多对 1 道
```

规则解析失败不等于模型一定没有写出答案，也可能是表达不被解析器识别。但这里的 official 微小优势不能证明答案质量更好。

按 LLM judge，r50 相对 r90 是 **83 道改对、111 道改错，净少 28 道**，即 -3.11 个百分点。question-level paired bootstrap（2,000 次、seed 42）的 95% 区间约为 **[-6.23, 0.00] 个百分点**，上界触及 0；不据此声称稳定或严格显著的差异。

## 建议

r50 适合作为观察“更频繁内容替换”的实验条件，但现有结果不支持仅凭 official 分数把它选作更好的默认方法。

优先把以下因素分开控制：

1. 已知 EOS 后限制提交候选到前缀，检查尾部等待能减少多少，以及答案是否变化；
2. 单独统计和对照正文尚未展开时的 EOS 提交，尤其是 contrast 将非 EOS 改为 EOS 的事件；
3. 在 r=0.5 下运行 `timing_only_crossed`，保持对比候选的门控/排序，实际写回 base，以区分更快的调度与内容改写带来的影响。

这些改动需要新的生成对照。当前报告的依据是离线记录，不能直接给出改动后的准确率或无损加速承诺。

复现脚本为 `scripts/mmmu_generation_patterns.py`；机器可读结果 `reports/mmmu_generation_patterns.json` 中新增了 `r50_vs_r90`、逐题空推理标记、末尾选项替换信息及 qualified 正文概率统计。
