# MMMU r90 机制检查

检查对象是 Native / CDAPC r90 / CDAPC r50 各 900 条相同 MMMU validation 题目。数据来自保存的 predictions、commit log、首个替换快照、official/strict scores 和 DeepSeek judge 结果；本检查没有重新推理或发起 judge 请求。

**结论：r90 的各执行路径在日志中保持一致，但直接对比替换非常稀疏，主要表现为严格筛选、少量提交和频繁 fallback。现有证据不能把准确率增加归因于视觉对比替换。**

## 机制触发

| 指标 | r90 | r50 |
| --- | ---: | ---: |
| 总迭代次数 | 70,047 | 28,237 |
| 窗口内候选位置观测次数 | 1,083,038 | 440,910 |
| contrast 与 base 不同的候选观测 | 233,584（21.57%） | 95,066（21.56%） |
| 通过门控的候选 | 162,283（14.98% 的观测） | 133,872（30.36%） |
| 真正写入的非 base token | 182 | 2,949 |
| 非 base 写入 / 全部写入 | 0.0928% | 2.1199% |
| 至少一次非 base 写入的题目 | 174/900 | 801/900 |
| 最终 EOS 前有非 base 写入的题目 | 160/900 | 700/900 |
| fallback 迭代 | 33,786（48.23%） | 5,238（18.55%） |
| 平均每轮提交 token 数 | 2.80 | 4.93 |
| EOS 前缀完成后提前停止 | 214/900 | 574/900 |

同一位置可能在多轮被观测，候选观测次数不是独立 token 数。W=K=16，使得窗口中所有 eligible 位置都可以提交；所以本次 qualified flips 等于 actual switches。

1. **视觉消融与对比分支**：顺序执行每轮两次前向，r90 总计 140,094 次，全部 900 条都与迭代数匹配。contrast 约在 21.6% 的窗口位置观测中不同于 base，表明对比计算并非恒等路径。执行代码对每层的非视觉 query → 视觉 key 加屏蔽 bias；消融分支仍能通过此前文本携带视觉信息，因此它不是完全无视觉信息的模型。
2. **beta 候选池**：对已提交位置，检查了 contrast 的原始概率至少为 base 概率的 0.1 倍。r90 的 162,283 个 qualified 写入中，158,968 个候选池只有一个 token（97.96%）。这些位置没有可供内容替换的第二候选；beta 与高 r 阈值共同使接受路径偏向高度确定的位置。没有 beta 消融，不能单独判断该机制的收益。
3. **r gate**：r90 的所有 33,786 次 fallback，在最终选中位置上都不满足 r≥0.9，其中 159 次也不满足 u≥0.1。没有出现仅 u 不通过而 r 通过的 fallback 选中位置。r 是 `pool_mass × softmax(contrast_score)[candidate]`，不是校准的答案正确率。
4. **u gate**：已提交 qualified 位置均满足 u≥0.1，最低约 0.10019。由于 full trace 关闭，不能统计所有未选位置的 u-only 拦截，也不能据此断言 u gate 完全无作用。
5. **fallback**：每次恰写一个 base token。1,968 次 fallback 选中位置的 contrast 与 base 不同，但最终按协议写回 base。候选排序采用 `min(u/0.1, r/0.9)`；日志不足以独立重算所有未选位置的排序。
6. **固定窗口与提交顺序**：窗口是最左 16 个尚未提交的位置，不是长度 16 的连续物理区间。70,047 轮全部满足窗口约束，无重复覆盖；50,466 轮（72.05%）提交后仍留下本轮最左的未填位置。窗口物理跨度均值 47.98、中位数 24、最大 256，反映出较多“跳过低置信位置，先写后面位置”的行为。动态窗口 CCAW 没有启用。
7. **迭代上限与停止**：r90 实际步数 1–243，没有触及 256 上限。214 条以 `eos_prefix_complete` 结束，686 条填满画布结束。每轮重建均确认：一旦已写 EOS 的前缀全部完成，就在该轮停止，没有发现停止条件违例。

## 对比替换主要改了什么

r90 的 182 次真实替换：

- 166 次位于最终可见文本中，15 次写入最终首个 EOS，1 次在 EOS 后。
- **116 次都是位置 3 的 `"\n" → " The"`**，即把 `<think>` 后的开头改成 `<think> The...`；占全部替换的 63.74%，占可见替换的 69.88%。
- 仅 5 次可见替换位于一个完整 `</think>` 之后。这不是所有“答案相关替换”的计数，因为答案也可能出现在 think 内。
- 部分剩余替换是 `question → image`、`image → diagram`、数字、选项字母、格式 token 等。

代表例子：

| 样本 | 同一状态下的 base → 实际写入 | 观察 |
| --- | --- | --- |
| `validation_Accounting_13` | 开头换行 → ` The` | 最终回答 A，gold C，judge 错误；格式改变不保证事实正确 |
| `validation_Art_25` | ` question` → ` image` | 最终回答 C / Andy Warhol，judge 正确 |
| `validation_Architecture_and_Engineering_28` | 开头换行 → ` The` | 生成出现 `<think> TheThe...`，但答案 B 被 judge 判对 |
| `validation_History_1` | `</think>` 后的 EOS → `B` | Native 错、r90 对；只能视作相关案例，不能当作单 token 的因果证明 |
| `validation_Biology_7` | `</think>` 后的 `B` → `0` | Native 与 r90 都被 judge 判错 |

这里的 base 是**同一 r90 解码状态**下视觉分支的 top-1，不是 Native 在同一位置实际生成的 token。

## EOS 与生成模式

r90 平均实际输出 114.62 tokens，但平均提交 217.85 个画布位置。196,069 次写入中：

- 可见位置 103,162 次；
- 最终首个 EOS 894 次；
- 最终 EOS 后 92,013 次，占所有写入的 **46.93%**；其中 92,009 次写的也是 EOS。

851 条题目在第一次写出某个 EOS 时，EOS 前仍有未填位置；在有 EOS 的 894 条中，从第一次写 EOS 到结束平均又运行 16.52 轮，中位数 13 轮。因此提前停止逻辑有效，但经常被前面的未填位置阻挡。

这些 EOS 后 token 最终不显示，不过模型使用双向注意力，它们仍可能影响随后提交的前文，不能直接视作完全无影响的计算。

r90 的 900 个文本中，721 个含完整 `</think>`（Native 673，r50 503）；105 个在最后一个 `</think>` 后没有非空文本。后者不等于没有答案，答案可能写在 think 内。r90 有 117 个输出不超过 5 tokens，6 个无 EOS、达到 256 token 上限。

## 是否改善答案

LLM judge：Native 227/900（25.22%），r90 247/900（27.44%），r50 219/900（24.33%）。

r90 对 Native 的逐题转移是 **107 条改对、87 条改错，净增加 20 条**。question-level paired bootstrap（2,000 次，seed 42）的差值 95% 区间为 **[-0.78, +5.22] 个百分点**，包含 0。

按实际替换分组：

| r90 组别 | 题数 | Native 错 → r90 对 | Native 对 → r90 错 | 净增加 |
| --- | ---: | ---: | ---: | ---: |
| 无任何实际替换 | 726 | 91 | 73 | +18 |
| 至少一次实际替换 | 174 | 16 | 14 | +2 |
| 含开头换行 → ` The` 替换 | 116 | 10 | 12 | -2 |

最后一行是上一行的子集。这是按生成结果事后分组的描述，不是随机消融。**净增加的 20 条里，18 条来自完全没有直接替换的轨迹**，因此当前数据不支持“主要靠对比 token 替换带来准确率提升”的解释。解码顺序、不同状态下的 top-1、每轮提交量等差异仍需单独控制。

## 校验范围与下一步

离线重建检查了 r90 的全部 900 条、70,047 轮，以及 r50 的全部 900 条、28,237 轮：

- 提交位置属于正确窗口、没有重复写入，qualified 顺序符合 r/u/位置排序；
- qualified 满足双门控且写 contrast，fallback 恰写一个 base；
- 候选池概率下界与 `r=mass*q` 一致；
- 重建画布、observed/eligible/committed/switch/fallback 指标与原记录一致；
- 前向次数和快照存在性一致，快照指向首个实际替换；
- 没有满足 EOS 前缀完成条件后仍继续迭代的记录。

这些是保存日志的内部一致性检查，不是重新运行模型，也不证明每一层 attention mask 的执行完全正确。

若要判断单个机制的因果收益，建议在固定协议下补充 `timing_only_crossed` 与 `gain_zero`，以及单独关闭 u/r gate 的消融。对少量固定样本开启完整 trace，才能统计所有位置的独立 gate 拦截、fallback 排序和未选候选。现有 `replay` 命令只支持 M3CoT，不能直接把 MMMU 快照当作已完成的反事实 replay 结果。

复现本次离线检查：

```bash
.venv/bin/python scripts/mmmu_mechanism_audit.py
```

机器可读结果：`reports/mmmu_mechanism_audit.json`，包含全部 r90 替换事件、相关样本正文、分布和 run 索引。脚本需要原始 run 目录；上传的摘要包不包含完整 predictions。
