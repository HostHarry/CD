# COCO think 质量下降诊断

基于5127个唯一输入、9000条评测记录、现有Judge结果及完整提交日志。
未调用新的Judge，未执行新的模型推理。逐输入证据与源文件哈希见同名JSON；
重算脚本为 `scripts/diagnose_pope_coco_quality.py`。

## 1. 已控制的差异：整套think提示协议

三个分片逐一核对：直答与think前缀组的模型资产、环境、生成源码哈希一致。
配置差异仅有run名称、prompt_id、评分parser_id；本诊断用同一个答案区域官方规则重评。
因此这一步测量的是整套提示协议的影响，尚不能拆成“推理指令”与“Final answer要求”的单独效果。

| 条件 | Accuracy % | F1 % | Yes比例 % |
|---|---:|---:|---:|
| 直答，EOS前缀候选 | 80.58 | 79.65 | 45.16 |
| think，EOS前缀候选 | 68.20 | 73.51 | 70.00 |
| think，原候选＋安全EOS | 69.23 | 73.97 | 68.16 |

切换提示协议下降12.38个百分点；恢复原候选回升1.03个百分点。
最大的已观测损失并非由EOS候选限制单独解释。

## 2. 格式解析确实损失分数，但明确错答更多

| 新原候选版分组 | 评测行 | 官方准确率 % | Judge准确率 % |
|---|---:|---:|---:|
| 闭合、非空、以Yes/No或Final answer标签开头 | 7724 | 72.28 | 71.08 |
| 未闭合且生成成功 | 1085 | 48.57 | 74.19 |
| 闭合后为空 | 82 | 65.85 | 74.39 |
| 闭合、其他格式 | 87 | 77.01 | 74.71 |
| 预算耗尽 | 22 | 0 | 0 |

分组指标为组内合并统计，不与完整数据的split均值混用。
“标签开头”只检查字面格式，不保证答案无矛盾。

同一文本改用Judge提取后，384行由错变对、194行由对变错，净回收190行，
即2.11个百分点。Judge为文本答案提取器，不看图片；这不等于对模型真实性的独立裁决。
未闭合组中存在 `<think>No`、损坏的结束标签等被官方默认判Yes的例子。

Judge口径下仍有2387行明确答错：1763行错答Yes、624行错答No；
另有98行歧义、72行缺答、22行预算耗尽。
仅“闭合且标签开头”组就有1646行官方误报，Judge也认定其中大量答案为Yes：
该组Judge误报1643行。低分不能只归为缺标签。

## 3. 提交轨迹：直接改写最终Yes不是主要现象

对能够定位到具体Yes/No token、且与Judge提取标签一致的记录作分析。
在1446个明确错答Yes的唯一输入中：

- 1428个（98.76%）最终标签与同一步正常视觉分支base完全相同。
- 1081个（74.76%）通过门控提交；其余365个走fallback。
- 最终标签平均在第67.33轮提交，此时约91.17%的最终可见位置已在更早轮次提交。

因此“最终Yes普遍在推理之前被过早写死”不受这批日志支持。
更符合输出证据的现象是：已有文本包含错误的存在判断，后续预测继续给出Yes；
该上下文中的base和r门控也可能支持错误答案。
base是同一CDAPC状态下的视觉预测，不是Native完整轨迹的输出。
这不能排除更早的对比改写或位置顺序产生间接影响。

全部可见token提交中，3296/218193（约1.51%）不同于base。
有2036个输出在 `<think>` 后直接以Yes开头，其中1916个与Judge最终判断一致；
598个以No开头的输出均与Judge最终判断一致。
这种一致性是行为证据，不证明思维链自我强化的因果方向。

未闭合的736个成功输入平均只有11.57个可见token，首次EOS平均在第3.86轮提交；
闭合且标签开头的4303个输入分别为47.51个token、第23.30轮。
这与短输出及较早形成EOS边界相关。不能据此指责安全停止截断了本可修改的前缀；
当前解码器的已提交位置本来就不可重写。

## 4. 相同192题上的外部小样本

将上传的Native提示词诊断按图像SHA256和原问题精确匹配到CDAPC输出。

| 方法/提示 | 正确数/192 | Accuracy % | Yes比例 % |
|---|---:|---:|---:|
| Native直答D | 147 | 76.56 | 41.15 |
| Native think B | 144 | 75.00 | 50.00 |
| CDAPC直答前缀 | 150 | 78.13 | 40.63 |
| CDAPC think前缀 | 128 | 66.67 | 70.83 |
| CDAPC think原候选 | 132 | 68.75 | 67.71 |

Native B没有Final answer后缀，使用L256/T256/B32；
CDAPC使用L256/I128/W16/K4。因此这不是隔离算法的消融。
它提示应优先研究提示词与解码规则的组合，不能解释为所有MMaDA think都必然退化。

## 5. 最小因果对照方案

先做2×2：Native/CDAPC × 当前think提示/去掉Final answer后缀的基线think提示。
固定图像问题、模型、画布长度、原生步数上限、温度、EOS安全条件、评分规则；
Native与CDAPC保留各自提交规则，此阶段测“整套解码器×提示词”的交互。
先按图像SHA256排序、固定选64张图及其所有POPE行，保留正负例与三split；
运行前锁定输入清单和哈希，禁止根据结果换样本。小样本用于机制筛查，非全量排名结论。

若去后缀不能恢复性能，再在独立快照中分离固定块/提交配额、门控和对比写入。
改变块边界时保持其余排序不变；改变quota时明确固定配额与上限的差别。
各项应分别对照，不一次修改多个机制后归因。

当前三张GPU仍执行已授权的A-OKVQA/GQA队列，本轮没有插入争抢GPU的推理。
在取得受控生成结果前，不能给alpha、r门控或K各自分配准确率损失。
