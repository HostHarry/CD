# MME r70，L256/I128 后续队列

用户于 2026-11-09 要求接上 MME，长度/预算为 256/128。
沿用当前 CD-APC r70 的 alpha/beta/u、W=K=16、seed、EOS 和图像预处理参数。
本条件采用官方 Yes/No 提示词，覆盖 14 类、2,374 题、1,187 个图像问题对。
官方主分数为各类别的 `100 × (Acc + Acc+)`，分别汇总 Perception / Cognition。

隔离工作目录：`/root/autodl-tmp/cdapc-mme`。
该目录快照了当前框架；添加 MME 的代码不会改变本目录正在运行的 MMMU/K
实验的生成源码指纹。源文件校验记录在隔离目录的 `reports/source_snapshot.json`。
模型权重和 MMaDA 上游源码复用已校验的文件；数据集、MME 评分器和新增依赖独立保存。

队列顺序：MMMU r70 生成 → K4 → K2 → MME r70。
MME 等待 K4/K2 生成结束，然后获取 `logs/benchmark_extensions/queue.lock`，
使用三张 GPU。CPU/API 评分可以与后续 GPU 生成重叠。

- 状态：`reports/mme_r70_256_128_runs.json`。
- 最终报告：`reports/mme_cdapc_r70_L256_I128.json` / `.md`。
- 控制器：隔离目录的 `scripts/run_mme_256_128.py`。
- 日志：隔离目录的 `logs/driver.log`、`logs/shard{0,1,2}.log`。
- 原始预测：隔离目录的 `runs/`。

数据 parquet 的 SHA256 与固定 HF 版本核对；题目和标签逐条对照官方评测包，
每张图的两题保持同分片。评分用官方原始答案解析器，并运行未经修改的官方脚本
核对全部 14 类得分。预算耗尽计错、保留在分母中，不使用 API 裁判。
